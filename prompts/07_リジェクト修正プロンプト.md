# 07　リジェクト修正プロンプト

LINEから届いた審査結果を貼り付けると、問題点・修正箇所・再申請前チェックを整理するプロンプト集です。

対応する章：**第8章　審査とリジェクト対応**

---

## 使う前に知っておくこと

> **リジェクトは失敗ではなく、修正指示です。**

そして、原因のほとんどは**画像の仕様**です。

まず、これを実行してください。

```powershell
# Windows
python scripts\validate_images.py output
```

```bash
# macOS
python3 scripts/validate_images.py output
```

**これだけで解決することが多いです。**

AIに相談する前に、機械的にチェックできる項目を潰してください。

---

## AIに使わせてはいけないこと

**重要です。**

AIは、LINEの規約を正確に持っていません。

だから、次のことをさせないでください。

- 規約の条文を引用させる
- 画像サイズの具体的な数値を答えさせる
- 「これで必ず通る」と言わせる
- 審査日数を答えさせる

**各プロンプトには、この制約を入れています。**

削らずに使ってください。

## プロンプト1　リジェクト通知を整理する（メイン）

```text
あなたはLINEスタンプ制作の経験者で、審査対応を支援する立場です。

以下は、LINE Creators Marketから届いた審査結果の通知です。
この内容を整理して、修正方針をまとめてください。

【審査結果の通知（原文）】
（ここに届いた通知をそのまま貼る）

【私の制作物の情報】
- スタンプ枚数：
- 画像の作り方：（例：画像生成AIでイラストを作成、文字は後から追加）
- キャラクター：（例：架空のAI活用コンサルタント）
- 使ったツール（生成・加工）：
- 画像サイズ：
- 透過の確認方法：（例：黒背景に重ねて確認した／していない）
- タイトル：
- 説明文：
- タグ：
- 販売地域：
- 写真の使用：あり／なし
- AI利用の申告：（どう回答したか）

【出力してほしいこと】

1. 指摘の要点
   - 通知に書かれている指摘を、箇条書きで整理する
   - **通知に書かれていないことを推測で追加しない**

2. 指摘の分類
   - 「画像の仕様」「権利」「内容」「設定・テキスト」のどれか
   - 対象ファイルが特定できるか、全枚数の確認が必要かを明記する

3. 修正箇所の特定手順
   - 何を、どの順番で確認すればよいか
   - 確認に使える方法（黒背景での透過確認、拡大確認など）
   - 自動チェックできる項目と、目視が必要な項目の切り分け

4. 具体的な修正作業
   - 作業内容を1ステップずつ書く
   - 画像編集ソフトでの操作として書く
   - 元ファイルを上書きしない手順にする

5. 再申請前チェックリスト
   - チェックボックス形式（- [ ]）
   - 今回の指摘に関係する項目を先頭に置く
   - 全枚数を確認する項目を明記する

6. 次回以降の予防策
   - 同じ指摘を受けないための工程上の対策
   - どの工程のどのタイミングで確認すべきか

【重要な制約】
- LINEの規約条文を推測して引用しないでください
- 通知に書かれていない基準や数値を創作しないでください
- 画像サイズなどの具体的な数値は
  「LINE Creators Market公式ガイドラインで要確認」と書いてください
- 審査日数について推測しないでください
- 「これで必ず通る」といった断定をしないでください
```

## プロンプト2　指摘が曖昧なときの絞り込み

対象のファイル番号が書かれていない場合に使います。

```text
LINE Creators Marketの審査で、以下の指摘を受けました。
しかし、対象のファイル番号が書かれていません。

【指摘内容】
（貼る）

【私の状況】
- 枚数：
- 画像の作り方：
- 加工に使ったツール：
- 気になっている点（自分で怪しいと思う箇所）：
- validate_images.py の実行結果：（貼る、または未実行）

【出力してほしいこと】
1. この指摘で考えられる原因を、可能性が高い順に5つ
2. 各原因について、確認する具体的な方法
3. 40枚全部を確認する場合の、効率的な手順
4. 自動チェックできる項目と、目で見るしかない項目の切り分け
5. 確認の優先順位（時間をかけずに絞り込む順番）

【制約】
- 通知に書かれていない基準を推測しないでください
- 確認方法は、無料ツールでできる範囲で書いてください
- 具体的な数値は「公式で要確認」と書いてください
```

## プロンプト3　類似画像の指摘に対応する

```text
「類似した画像が複数ある」という指摘を受けました。

以下は、40枚のスタンプのセリフ・表情・ポーズの一覧です。

【一覧】
（stamp_list.csv の内容を貼る）

【出力してほしいこと】
1. 表情とポーズの組み合わせが似ているペアを、すべて挙げる
2. 各ペアについて、どちらを残すべきか（理由付き）
3. 残さない側を作り直す場合の、新しい表情・ポーズの案
4. 40枚全体で表情のバリエーションが足りているかの評価
5. 表情の使用回数の集計（偏りの確認）

【判定の基準】
- 「文字を隠したときに、絵だけで違いがわかるか」で判定する
- 表情の差が小さいものは類似とみなす
- 手の位置だけが違うものは類似とみなす
- 体の向きだけが違うものは類似とみなす

【出力形式】
| ペア | 類似の理由 | 残す方 | 作り直す方の新しい案 |
```

## プロンプト4　透過・仕様の指摘に対応する

```text
画像の仕様について指摘を受けました。

【指摘内容】
（貼る）

【validate_images.py の実行結果】
（貼る）

【私が使っている加工ツール】
（例：Photopea / Canva / ibisPaint）

【出力してほしいこと】
1. 実行結果から読み取れる問題の一覧
2. 各問題について、私が使っているツールでの修正手順
   （メニュー名・ボタン名を具体的に）
3. 修正後の確認方法
4. 全枚数に同じ問題がある可能性の判定
5. 元ファイルを上書きしない作業手順

【条件】
- ステップごとに「確認すること」を1行添える
- ツールのバージョンによって名称が違う可能性を明記する
- 数値は私が公式ガイドラインで確認する前提で書く
- 修正後に validate_images.py を再実行する手順を含める
```

## プロンプト5　セリフ・内容の指摘に対応する

```text
「内容が不適切」という指摘を受けた可能性があります。

以下のセリフ40個を確認し、審査で問題になりうる表現を洗い出してください。

【指摘内容】
（貼る。書かれていない場合は「対象不明」と書く）

【セリフ40個】
（貼る）

【チェック観点】
- 差別的・侮辱的に読める表現
- 攻撃的な表現
- 性的な表現
- 危険な行為を勧める・想起させる表現
- 賭博を想起させる表現
- 実在人物・団体・商標・ブランド名
- 医療・健康・法律について断定している表現
- 宗教・政治に関する主張
- 特定の地域や文化で受け取り方が変わる表現
- 特定の職業・属性を下に見る表現

【出力形式】
| No | セリフ | 懸念点 | 言い換え案 | 削除を推奨するか |

【最後に出力すること】
削除した場合の枚数調整の方法
（40個から減る場合、32個にするか、代わりのセリフを作るか）

【制約】
- 規約の条文を推測して引用しないでください
- 「これは絶対に問題ない」という断定をしないでください
- 最終判断は公式ガイドラインを確認する前提で書いてください
```

## プロンプト6　説明文・設定の指摘に対応する

```text
説明文またはタイトル、タグについて指摘を受けた可能性があります。

【指摘内容】
（貼る）

【現在の入力内容】
- タイトル（日本語）：
- タイトル（英語）：
- 説明文（日本語）：
- 説明文（英語）：
- タグ：
- 販売地域：
- 写真の使用：あり／なし

【セリフ40個（照合用）】
```

```text
著作権・商標・肖像権について指摘を受けた可能性があります。

【指摘内容】
（貼る）

【私の制作方法】
- 使った画像生成AI：
- 生成プロンプト（実際に使ったもの）：
  （貼る）
- キャラクター設定：
  （貼る）
- 小物として描いたもの：
- 参照した画像：あり／なし（ありの場合は内容）

【出力してほしいこと】
1. 生成プロンプトの中で、権利上のリスクになりうる記述
   （作品名・作家名・「〇〇風」の指定・実在人物の名前など）
2. キャラクター設定の中で、既存作品と一致しやすい要素
3. 小物に含まれる可能性のある商標的要素
```

```text

次の作品で同じ失敗をしないよう、記録を整理してください。

【今回の記録】
- 指摘された項目：
- 対象ファイル：
- 原因（自分の分析）：
- 行った修正：
- 修正にかかった時間：
- 結果：（承認された／再度リジェクト）

【出力してほしいこと】
1. 失敗の分類（企画 / 設計 / セリフ / 生成 / 加工 / 申請）
2. 根本原因
   （「確認していなかった」で終わらせず、工程の問題として書く）
3. 次回の工程に追加すべきチェック項目（チェックボックス形式）
4. その項目を、どの工程のどのタイミングで確認するか
5. 自動化できる項目と、目視が必要な項目の切り分け
6. production_checklist.md に追加すべき行

【出力先】
lessons_learned.md として保存できるMarkdown形式
```

## 再申請前チェックリスト（共通）

指摘の内容にかかわらず、これは毎回確認してください。

### 画像の仕様

- [ ] `validate_images.py` を実行して全項目OK
- [ ] 黒背景で全枚数の透過を確認した
- [ ] 白いフチが残っていない
- [ ] キャラクターが端に接触していない
- [ ] 文字が切れていない
- [ ] 縦横のピクセル数が偶数
- [ ] 中身が本当にPNG（スクリプトで確認）
- [ ] `main.png` と `tab.png` がある
- [ ] ファイル名が3桁連番

### 権利

- [ ] 小物を拡大して、文字・ロゴがないことを確認した
- [ ] 実在人物・既存キャラクターを想起しないか確認した
- [ ] 生成プロンプトに作品名・作家名を入れていない
- [ ] フォントの商用利用条件を確認した
- [ ] 画像生成AIの商用利用条件を確認した

### 内容

- [ ] 40枚を並べ、文字を隠して絵だけで違いがわかった
- [ ] セリフ40個の表現を見直した
- [ ] 差別的・攻撃的・性的な表現がない

### 設定・テキスト

- [ ] 説明文が、実際のセリフの範囲と一致している
- [ ] タイトルにキーワードを詰め込んでいない
- [ ] 誇張表現を入れていない
- [ ] タグが内容に合っている
- [ ] AI利用・写真使用の申告が事実どおり

### 差し替え作業

- [ ] 修正した画像を**同じファイル名**で差し替えた
- [ ] 元画像を別フォルダに保管している
- [ ] 修正後に `validate_images.py` を**再実行**した
- [ ] プレビューで確認した
- [ ] スマートフォンで実サイズを確認した
- [ ] 修正記録を残した
